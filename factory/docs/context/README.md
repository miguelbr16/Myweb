# docs/context/

## Propósito

Documentos de **contexto estable** del proyecto: visión, situación actual, recursos, restricciones, oportunidades detectadas y estado del equipo.

Sirven como onboarding para cualquier colaborador (humano o IA) que entre al proyecto.

## Qué debe vivir aquí

- Contexto consolidado del proyecto (p. ej. `DIGITAL_FACTORY_CONTEXT.md`)
- Descripción de situación actual y restricciones
- Oportunidades de mercado **como hipótesis** (no como datos validados)
- Inventario de recursos y herramientas disponibles

## Qué NO debe vivir aquí

- Decisiones arquitectónicas cerradas → `docs/architecture/` o `decisions/`
- Specs ejecutables → `specs/`
- Playbooks operativos → `docs/playbooks/`
- Aprendizajes post-entrega → `docs/learnings/`
- Código, configs, secrets
- Datos de mercado inventados o no verificados presentados como hechos
